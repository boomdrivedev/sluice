# The host that keeps a branch takes its pull requests in, and no intake mark is kept

Status: accepted. Under the statement's 137 and record 0093 as amended on 2026-11-08, which the user accepted that day, the form below, decisions 1 to 8, is the construct stage's own, from the change's design D21 to D28; each is cheap to change. It amends records 0095 and 0096 in part.

Deciders: the design and the construct stage of the change `one-sluice-process-runs-each-hosts-queues`.

Sources: the statement in boomdrivedev/blueprints, `design/sluice/requirements.md`, clauses 26, 56, 67, 72, 73, 120, 128, 133, 137 and S64, C.5's pull request row and C.6; records 0088, 0093 as amended 2026-11-08, 0095 and 0096; rules core.11, core.14, core.27, core.28 and core.33; the change's design D21 to D28; `crates/sluice/src/profiles/github/pulls.rs` (`takes`, `take_in`, `across`, `kept_across`, `opening`), `crates/sluice/src/profiles/pushed_refs.rs`, `crates/sluice/src/profiles/github/kept.rs`, `crates/sluice-core/src/policy.rs` (`Rules`, `rules_for`, `remote_of`), `crates/sluice-core/src/lib.rs` (`note_intake_refused`, `note_intake_read`, `carry`), `crates/sluice/src/lib.rs` (`intake`, `TakenInBy`, `Across`) and `crates/sluice/src/host_process/pass.rs`.

## Context and problem statement

Record 0093 as amended on 2026-11-08 has a branch's queue run whole by whatever executes it, and its requests taken in by that executor alone, never by two. Until this change, where each host kept a branch's records, the holder of an intake mark, `refs/sluice/intake/<branch>` on the remote, took its requests in: a driver pushed and renewed the mark, a wait held it among its host's waits, and a host that found another's mark handed its own requests over by withdrawing them. Records 0095 and 0096 built a host's view of requests another host takes in on that mark. With one host process per host and a branch's records on its remote, the host that keeps the branch there, the lead its records name (72), is that one taker. What becomes of the mark, of a branch whose records each host keeps, of an older mark or hand-over, and of what intake could not ask?

## Considered options

- Keep the mark beside the lead, for branches whose records each host keeps.
- Let every host take in a branch whose records each host keeps.
- Take requests in only where a host keeps the branch on its remote, refusing a branch that takes pull requests on records each host keeps.

## Decision outcome

The third.

1. **The instance that keeps the branch takes its requests in** (D21). `Pulls::takes` answers `Here` where the branch's records are on its remote and this instance keeps it, and otherwise `Elsewhere` with the lead its records name, or none yet. Any process of that host takes them in under intake's lock, a pass, a step and a submit's own first intake alike, so the records' one lead and intake's one lock make one taker (72; core.14). A host that does not keep the branch asks GitHub nothing of its open requests, withdraws nothing, and follows its own requests by GitHub's word and sluice's check. *Not taken:* every host taking in a branch whose records each host keeps, each request taken in once per host (137); the first host that finds no lead in a file or ref of its own, which is a mark by another name (core.33).
2. **A pull request table on records each host keeps refuses its branch alone** (D22). `Rules` gains `unkept`, and `Policy::rules_for` refuses that branch alone: `main takes pull requests, which only the host that keeps it on origin takes in, and its state is each host's own: name [signers] in .config/sluice.toml so its state is kept on origin (137)`, in the words the site gives the reader, its state rather than its records (core.26). Routing reads the branch's remote by `Policy::remote_of` whatever its table refuses (core.27). A submit to it exits 2 before anything is pushed or opened; a step, a pass and intake pass it by with its words; a status shows them. *Not taken:* the whole policy refused (S64); the table accepted and its requests left waiting for a taker that never comes (137); the table's intake alone refused, half a branch kept. The overview lists the refused branch only where it has records; listing every branch the default policy names, records or none, is the path not taken there.
3. **Nothing of the mark is kept, and nothing reads an older one** (D23). The mark's refs, its fetch and its `--prune`, and the host's kept intake state, `forge/intake/`, go. A mark an older sluice left is fetched, read and deleted by nothing; the pull requests guide says how to delete it by hand. *Not taken:* a sweep pushing to a ref sluice no longer owns, which an older sluice on another host still reads.
4. **No hand-over is written, and an older one is read as written** (D24). `Requester::HandOver` and `Sluice::drop_obsolete` go; a round still drops the combinations every other withdrawal makes obsolete. `Withdrawal::handed_over_to` and `Event::Withdrawn`'s are read and never written: an older hand-over holds no request (record 0088 as amended; core.48), so a branch whose records move onto its remote takes each such request in again at its head with no draft, and a wait on it follows what carries its work. With no withdrawal for a hand-over, a request keeps one submission and one number from intake to landing. *Not taken:* an older hand-over read as any withdrawal, holding its request as a draft for an act no submitter made (120).
5. **A host that does not keep the branch shows the requests it follows** (D25). Record 0095's rows become every host's that does not keep a branch on its remote: `taken_in_by` is `{"host": <lead>}`, `null` where none leads, and `holder` goes. The host process's reading, a pass or a look, reads each followed request as it falls due at the host's one bound; a status, the overview and the reader's document carry the rows as the host last kept them, read again once the kept follows or the lead moved. *Not taken:* no rows, which 137's last sentence rules out; `taken_in_by` dropped, which crew reads.
6. **A step and a submit say what intake met** (D26). `PullRequests::intake` returns whether the branch takes pull requests, whether its pass asked the forge, and each cause it met, what it asked, `<branch>'s pull requests` or `pull/<n>`, and the forge's words; nothing in intake prints. `sluice step` says each on stderr, `sluice: warning: taking in <branch>'s pull requests: <asked>: <said>`, every step; a submit's own first intake says each on its stderr. The spent allowance's line stays said once for its pause (134). *Not taken:* a step reading the host process's log for its round's lines, which another round may write between.
7. **A standing intake failure is kept, logged and said as a refused read is** (D27). The records seam keeps this host's refusal of a branch's intake in the form of its refusal of the remote, `intake/<branch>.json` beside `refused/<branch>.json`; `read-refused` and `read-again` gain `intake`, skipped where false. Each pass notes its causes, a `read-refused` marked `intake` written once for each in a write of its own where the branch's lock is free and by the next write otherwise; a pass that asked the forge and met none ends it with a `read-again` so marked, and one that asked nothing leaves it standing. A pass says a cause in the host process's log only where its note logged it, read from the kept document, so a restarted host process, a step and a submit say nothing again (core.11, core.14). `sluice status <branch>` says it above the queue and `--json` carries it as `intake_refused`. *Not taken:* the round's own refusal document, which every round that read the branch would end; events of their own, which an older sluice fails on reading a branch's log on its remote; a count at every refusal, a write per pass.
8. **The suite, and the changes built on the mark** (D28). The pull requests suite keeps `main`'s records on its bare remote, signed, the host keeping `main` and its host process passing only when asked; a test across hosts lets another host's pass run first. The tests of the mark, its lease, holds, renewal and hand-over go or are rewritten to the host that keeps the branch. The two unarchived changes built on the mark, `a-host-hands-over-only-to-the-host-its-mark-names` and `a-hand-overs-withdrawal-holds-no-request`, are removed.

## Consequences

- sluice's own `main` and WilldanGroup/switchboard-kit's `main` take pull requests and name no `[signers]`: each is refused on the release that carries this until its policy names signers whose keys its hosts hold, which is ops' to choose. Naming `[signers]` keeps every branch with a `remote` on its remote (C.6).
- Records 0095 and 0096 are amended in part: their reads of the mark's host become reads of the lead the branch's records name, and the hand-over they read is an older sluice's, read and never written.
- Rule core.33's details rule out a pull request table accepted on a branch whose records each host keeps and a host taking in a branch it does not keep; core.28's rule out an intake failure said only in the host process's log, or said again at each pass or start.
- A remote's `refs/sluice/intake/<branch>` and a host's `forge/intake/` may be removed by hand once every host runs this sluice.
