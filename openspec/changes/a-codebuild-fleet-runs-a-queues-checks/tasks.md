# Tasks

Work in this change's place on `change/a-codebuild-fleet-runs-a-queues-checks`,
cut from `bolt/sluice-is-refactored-and-runs-on-pools`, which is its base and
its gate (S66). Read the proposal, the design and the delta specs first, then
record 0119 with its amendment of 2026-11-16, timber's record 0017
(`boomdrivedev/timber`, `docs/adr/0017-the-key-service-signer-takes-a-p-256-key-by-its-arn-and-reads-its-standing-from-its-state.md`)
and `docs/architecture/core.md`. Each task leaves the tree building and its
named check passing. A quick unit test runs directly with `cargo test`; a test
that starts git, a process or the binary runs through sluice against the base,
as CLAUDE.md's "Running checks" has it: `sluice exec
bolt/sluice-is-refactored-and-runs-on-pools -- cargo test …`. Several names
after `--` run each test whose name holds one of them. No test reaches AWS: the
profile's unit tests use its fake (`profiles/codebuild/fake.rs`), and a
command-line test points the SDK at `crates/sluice/tests/support/http.rs`'s
fake server with `AWS_ENDPOINT_URL_CODEBUILD`, `AWS_ENDPOINT_URL_S3`,
`AWS_ENDPOINT_URL_KMS` and `AWS_ENDPOINT_URL_STS`, static credentials and no
profile, answering as CodeBuild, S3, KMS and STS answer, its KMS signing with a
P-256 key the test holds. Tests use scratch repositories and a bare clone
standing for the remote, never the host's own sluice state; every git call a
test makes runs with no credential helper and no prompt. Commit by pathspec,
Conventional Commits scoped to the part of the tree (`core`, `seams`,
`records`, `forge`, `codebuild`, `cli`, `devenv`, `site`, `docs`), citing the
clauses, record 0119, rules by id and the design's decisions by D-number.

## 1. The policy
