# Tasks

Work in this change's place on `change/one-sluice-process-runs-each-hosts-queues`,
cut from `bolt/sluice-is-refactored-and-runs-on-pools`, which is its base and its
gate (S66). Each task leaves the tree building and its named check passing.
A quick unit test runs directly with `cargo test`; a test that starts the
binary, git or a host process runs through sluice against the base, as
CLAUDE.md's "Running checks" has it: `sluice exec
bolt/sluice-is-refactored-and-runs-on-pools -- cargo test …`. A filter after the
test target runs each test whose name holds it. New tests on disk go in
`crates/sluice/tests/host_process.rs`, a target of the fast tier built on
`support::OnDisk`, with the `command` runner and real git; it carries no
`tools` gate. The old bolt's code at `e61acba` and `47ef4b8a`
(`git show 47ef4b8a:crates/sluice/src/host_process/<file>`) is the reference
for every decision the design marks as the old bolt's: port it onto main's
code, keeping main's behaviour where main moved since. Tests use scratch
repositories, a bare clone standing for GitHub's git and the GitHub double,
never a real account or the host's own sluice state. Commit by pathspec,
Conventional Commits scoped to the part of the tree (`seams`, `core`,
`fakes`, `cli`, `host_process`, `places`, `pulls`, `site`, `plugins/sluice`,
`docs`), citing the clauses, rules by id, and the design's decisions by
D-number. A test named as rewritten keeps its name unless a new one is
given. Site pages, skills and records land in the group whose behaviour
they describe.
