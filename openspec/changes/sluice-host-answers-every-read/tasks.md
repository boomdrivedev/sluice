# Tasks

Each check runs through sluice, one suite at a time: `sluice exec main -- cargo nextest run -p sluice --test <suite> <test>`. A test of a read that starts `sluice host` gives it a state folder of its own under the test's folders, so the guard finds and stops it. A test that says a command "ran no git" runs the command with no git on its `PATH`, after `sluice host` started with git.

## 1. The protocol

- [ ] 1.1 Add the requests `status`, `overview`, `home`, `forecast` and `inbox`, each with its folder and its command's arguments, and the answer `output` with `stdout`, `stderr` and `code`. Remove the requests `read`, `follow` and `room` and the answers `read` and `room`. Keep `serve`, `step`, `pass`, `hold`, `results` and `hand-over`. Check: `cargo nextest run -p sluice --lib host_process::protocol::tests`, with a test that the new requests read back.
- [ ] 1.2 Add `subscribe`, its `add` lines with `as` (`watch`, `wait` or `run`) and its `remove` lines, and the answers `document`, with `folder` and `overview`, and `pass`, with `folder` and `report`. Check: `cargo nextest run -p sluice --lib host_process::protocol::tests::a_subscription_reads_back`.
- [ ] 1.3 Answer a request that `sluice host` does not know with the error that names the client's version and the version of `sluice host`, and says to run sluice of that version (`host_process/mod.rs:answer`). Check: `cargo nextest run -p sluice --test host_process an_older_read_gets_the_host_processs_version` and `an_older_follow_gets_the_host_processs_version`, whose clients say `hello` as 0.97.0 and send `read` and `follow` from the test.
