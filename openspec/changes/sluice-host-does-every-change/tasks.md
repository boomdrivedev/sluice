# Tasks

Each check runs through sluice, one suite at a time: `sluice exec main -- cargo nextest run -p sluice [--features tools] --test <suite> <test>`. A test that says a command "ran no git" runs the command with no git on its `PATH`, after `sluice host` started with git. A test that says a command "read no forge" runs it with `SLUICE_FORGE_API` naming an address that refuses each call, after `sluice host` started with the test's forge. A test that starts `sluice host` gives it a state folder of its own under the test's folders, so the leak guard finds and stops it.

## 1. The protocol

- [ ] 1.1 Add the requests `submit`, `amend`, `withdraw`, `set-aside`, `confirm`, `push`, `release`, `branch`, `protect`, `previews`, `exec`, `preview`, `equip` and `reference-transaction`, each with its folder, its command's arguments and `caller`, and `run_env` for `exec`, `preview`, `equip` and `release`. Add the streamed answers `stdout` and `stderr`, which come before `output`. Check: `cargo nextest run -p sluice --lib host_process::protocol::tests`, with a test that each new request and answer reads back.
- [ ] 1.2 Remove `serve`, `hold` and `results`, and have `step` and `pass` name a folder (design D8). Check: `cargo nextest run -p sluice --test host_process an_older_serve_gets_the_host_processs_version` and `a_step_from_a_folder_runs_no_git`.
- [ ] 1.3 Add `TRACEPARENT` to the variables that `caller` carries, and have `caller::var` answer it in a request's call (design D1). Check: `cargo nextest run -p sluice --test host_process a_submit_names_its_agent` and `cargo nextest run -p sluice --test telemetry a_submits_trace_names_its_callers_span`.

## 2. sluice host makes each change

- [ ] 2.1 Answer `amend`, `withdraw`, `set-aside`, `confirm`, `push`, `release` of a checkout or a preview, `branch` and `protect` with one `spawn_blocking` call each, which binds the repository as the host holds it and renders the command's output, and then tells the repository's scheduler of the change (design D1). Send each from `main.rs` before the command binds a repository. Check: `cargo nextest run -p sluice --test host_process a_withdrawal_runs_no_git`, `an_amend_a_set_aside_and_a_confirmation_run_no_git` and `a_change_with_no_host_process_that_answers_exits_3`, `cargo nextest run -p sluice --features tools --test remote_branch a_branch_made_on_its_remote_runs_no_git`, and `cargo nextest run -p sluice --features tools --test pull_requests sluice_push_runs_no_git`.
- [ ] 2.2 Write a submit's submission in `sluice host`, from each worktree's folder that `submit` names, and answer with its number. A waiting submit then sends `wait`. Check: `cargo nextest run -p sluice --test host_process a_submit_with_no_git_names_the_worktrees_head`, `a_submit_with_no_host_process_running_lands` and `ten_submits_at_once_start_one_host_process`.
- [ ] 2.3 Make a pull request's submit in `sluice host`: the push as a git worker, the request opened or updated, marked ready and taken in (design D2). Check: `cargo nextest run -p sluice --test pull_requests a_submit_to_a_branch_that_takes_pull_requests_reads_no_forge`.
- [ ] 2.4 Take each step of a wait on a pull request, of a wait on a branch that takes pull requests, and of a group's wait in `sluice host`, on the subscription of `wait` (design D2). Check: `cargo nextest run -p sluice --test pull_requests a_wait_on_a_request_that_lands_reads_no_forge`, `cargo nextest run -p sluice --test cli a_groups_wait_runs_no_git`, and the suites `pull_requests` and `reader_tick` whole.
- [ ] 2.5 Answer `previews` as a read (design D1). Check: `cargo nextest run -p sluice --features tools --test previews_tools the_previews_are_answered_by_sluice_host`.
- [ ] 2.6 Remove the binding of the repository from `main.rs` for each command but `host`, `daemon`, `hand-over`, `supervise`, `job`, `credential`, `forge check`, `pool check` and `init`, and remove the client's sends of `serve` (`lib.rs:dispatch`). Check: `cargo nextest run -p sluice --test cli a_client_binds_no_repository`, which runs each change command and each read with no git on its `PATH`.

## 3. Sessions, previews and equips run in sluice host

- [ ] 3.1 Start a run's supervisor only as a worker of `sluice host`, and remove the start in a session of its own (`runs.rs:Runs::start`). Check: `cargo nextest run -p sluice --features tools --test exec a_sessions_checks_are_a_worker_of_sluice_host` and `cargo nextest run -p sluice --features tools --test previews_tools a_previews_command_is_a_worker_of_sluice_host`.
- [ ] 3.2 Answer `exec` in `sluice host`: the plan, the equip, the forecast, the slot from the host's own room in the run bound's order, the supervisor, and the run's log sent as `stdout` or `stderr` lines as it grows (design D3). Print each line in the client as it comes. Check: `cargo nextest run -p sluice --features tools --test exec the_output_reaches_the_client_as_it_comes` and `a_sessions_checks_take_a_slot_of_the_bound`, and the suite `exec` whole.
- [ ] 3.3 Give a run the kept variables of `run_env` in place of the environment of `sluice host` (design D4, `profiles/checks.rs:environment`). Check: `cargo nextest run -p sluice --features tools --test exec a_session_run_takes_its_callers_path`.
- [ ] 3.4 End a session's run, give its slot back and record it stopped when its connection closes, and end a wait for a slot the same way (design D3). Check: `cargo nextest run -p sluice --features tools --test exec ctrl_c_ends_a_sessions_checks`, `a_killed_client_ends_its_checks` and `cargo nextest run -p sluice --test host_process an_agents_check_stopped_while_it_waits_is_counted_nowhere`.
- [ ] 3.5 End a session's checks with `sluice host`, and have the client say so and exit 3. Check: `cargo nextest run -p sluice --features tools --test exec a_stopped_sluice_host_ends_a_sessions_checks`.
- [ ] 3.6 Answer `preview` in `sluice host`, with its command as a worker that stays after the connection closes, until its release. Check: `cargo nextest run -p sluice --features tools --test previews_tools a_preview_stays_after_its_client_ends`, and the suites `previews` and `previews_tools` whole.
- [ ] 3.7 Answer `equip` in `sluice host`, its steps streamed, with the worktree's top resolved from the folder. Answer `release` of a worktree with its release command as a worker. Check: `cargo nextest run -p sluice --features tools --test equip_tools sluice_equip_with_no_tools_of_its_own` and `cargo nextest run -p sluice --features tools --test exec a_worktrees_release_runs_in_sluice_host`.

## 4. The git hook asks sluice host

- [ ] 4.1 Send the transaction, the folder, `GIT_DIR` and git's command line as `reference-transaction`, and refuse where `sluice host` does not answer within ten seconds, with words that name `sluice protect --remove` (design D5). Check: `cargo nextest run -p sluice --features tools --test protect a_persons_write_is_judged_by_sluice_host`, `a_hook_with_no_sluice_host_running_starts_it` and `a_hook_whose_sluice_host_does_not_answer_refuses`.
- [ ] 4.2 Judge the transaction in `sluice host` from the state that it keeps, on the connection's task with no wait for a round or a reading, and write each refused write under the branch's lock. Check: `cargo nextest run -p sluice --features tools --test protect a_commit_during_a_long_round_ends_at_once`, and the suite `protect` whole, each changed to assert that the hook read no file of the records.
- [ ] 4.3 Give each git command of `sluice host` `SLUICE_HOST_PROCESS`, take it out of each check, session command, preview command, release command and equip step, and let a transaction that carries a live value go with no ask (design D6). Check: `cargo nextest run -p sluice --features tools --test protect a_fetch_whose_packing_runs_the_hook_asks_nothing`, `a_check_that_writes_main_is_refused` and `a_name_that_an_ended_sluice_host_gave_is_asked`.
- [ ] 4.4 Put back the hook in `sluice host` by its own path, for each repository that it binds for a request, and install it where a submit, a wait or a step names the repository. Remove `protection` from `main.rs` (design D7). Check: `cargo nextest run -p sluice --features tools --test protect a_newer_sluices_next_command_puts_back_the_hook`, `a_removed_hook_is_not_put_back_by_a_reading_command`, `sluice_protect_runs_no_git` and `a_sluice_on_the_callers_path_is_not_the_one_that_judges`.

## 5. Records, rules and the gate

- [ ] 5.2 Rewrite the rules that this change departs from, in the form that the rules have when it lands: the rule that `sluice host` alone reads a repository's records, for the hook and for a command that puts back the hook; the rule on a check's process group, for a session's run that `sluice exec` starts in a session of its own; and the rule on a write that the protection refused, for the hook's write of it. Each says Before and Now. Check: `sluice exec main -- moon run root:changes`.

No gate task reads a page's words, by the rule that no task reads Markdown, so the review of the diff checks it. Check: `sluice exec main -- moon run plugin-sluice:validate`.
